# Academy, payments and delivery — 5 November 2026

## Implemented

- Customer enquiry acknowledgements and staff alerts use a dedicated durable email_jobs queue. Each recipient has an independent idempotency key, bounded request, lease, retry schedule and provider reference. Signed Resend/Svix events record actual delivery/bounce/complaint state; acceptance is not described as delivery. A protected daily Vercel job (free-compatible) and staff retry control process eligible work. Automatic retries stop outside the provider's safe idempotency window; staff must review uncertain older messages. Legacy enquiry/outbox records are preserved; the new queue handles new submissions.
- Paystack hosted checkout uses server-owned course fees/currency, confirmed signed-in identities, unique references and pending-attempt reuse. Checkout URLs are restricted to Paystack. Both callback verification and signed webhooks re-query the provider and match amount, currency, environment and customer against the stored transaction. Settlement is atomic/idempotent. Modern timestamped signing secrets and legacy signatures are supported; configured modern verification never falls back to legacy. Test payments never unlock paid enrolment. Live collection additionally requires explicit company approval and matching live credentials.
- Learners have actual profile/progress, payment history/PDF receipts, support tickets/replies, versioned assessments, server-side scoring and attempt limits. Answer keys have no client access. Course completion certificates require current assessment pass, published lesson completion, active enrolment and a learner profile. Certificates have private Unicode-capable PDFs, opaque public verification references and administrator withdrawal/restoration. No manufacturer accreditation or signature is invented.
- Staff can edit course descriptions, objectives, prerequisites, duration, fee, status and instructor association; edit lessons; build assessments; review support; manage certificate status; export enrolments; and review email/payment operations. Existing enrolment approval, private PDFs and course creation remain available in the main workspace.
- Additive hosted migrations are 20261105142057_academy_commerce_delivery.sql and 20261105142305_academy_explicit_grants.sql. Local versions match hosted history. Supabase's default public-schema privileges were explicitly narrowed in the latter migration; RLS remains enabled throughout. Client privileges exclude answer keys, result/certificate creation and payment settlement. No customer data was deleted.
